# Тестирование

## 1. Уровни

| Уровень | Что проверяет | Где |
| --- | --- | --- |
| Unit | кадр, CRC, команды, декодеры, hex | app/app/src/test |
| Build | компиляция debug и release | Gradle |
| Lint | статические ошибки и предупреждения | lintDebug |
| Demo | UI, журнал, состояния без BLE | приложение |
| Hardware | реальный GATT и прошивка | телефон и самокат |

## 2. Unit-тесты

Запуск:

```
cd app
.\gradlew.bat --no-daemon testDebugUnitTest
```

FrameCodecTest проверяет:

- CRC8 на строке 123456789 равен A1;
- CRC8 пустого массива равен 0;
- CRC16 на строке 123456789 равен 4B37;
- сборка и разбор кадра сохраняют cmd, key, rand, payload;
- key и cmd ксорятся неразделённым rand;
- payload больше 255 байт отклоняется;
- плохой CRC отклоняется;
- поиск кадров пропускает мусор и разделяет поток;
- неполный хвост сохраняется;
- одиночный A3 в конце сохраняется;
- поиск восстанавливается после битого кадра;
- плохой заголовок и усечённый кадр отклоняются;
- hex и hexByte форматируют верхним регистром;
- parseHex принимает пробелы, запятые, двоеточия, дефисы и префикс 0x;
- parseHex отклоняет нечётную длину, не-ASCII цифры и мусор;
- кадр с пустым payload корректно находится.

ScooterCodecTest проверяет:

- keyCommand использует key=0 и ASCII payload;
- unlockCommand соответствует NineHack, 10 байт 01;
- lockCommand содержит 01;
- ejectBatteryCommand содержит 05;
- findCarCommand использует 0xA2 и 01;
- setScooterFromUi отображает флаги и режим;
- режим ограничивается 1..3;
- spamUnlockCommand содержит 01 31 31 32 39, время big-endian и 00;
- vehicleInfo декодирует батарею, режим, скорость, пробег и запас;
- короткий vehicle payload отклоняется;
- iotInfo инвертирует бит блокировки;
- ASCII device info определяется по двоеточию и печатным символам;
- realtime декодирует ток и флаги;
- RFID читает 4 байта и пару из 8 байт;
- короткие RFID payload отклоняются.

## 3. Тест-векторы

references/frames.json содержит детерминированные кадры с фиксированным rand. Проверка:

```
python references/verify_frames.py
```

Ожидаемый вывод: ok 72. Скрипт независимо разбирает 48 TX, 20 RX и 4 битых кадра, проверяет CRC8 и CRC16.

references/opcodes.csv содержит 54 опкода. Проверка количества:

```
python -c "import csv; r=list(csv.DictReader(open('references/opcodes.csv',encoding='utf-8'))); print(len(r))"
```

Ожидаемый вывод: 54.

## 4. Ручная матрица Android

| Сценарий | Ожидание |
| --- | --- |
| Первый запуск без разрешений | запрос BLUETOOTH_SCAN, CONNECT, POST_NOTIFICATIONS |
| Отказ в разрешениях | сообщение, демо-режим доступен |
| Bluetooth выключен | предупреждение, скан не начинается |
| BLE не поддерживается | сообщение, демо-режим доступен |
| Скан с фильтром UART | только устройства с UUID |
| Скан без фильтра | все BLE-устройства |
| Подключение к неизвестному устройству | ошибка UART service not found |
| Подключение к самокату | DISCOVERING, затем AUTHENTICATING |
| Неверный ключ | ошибка, READY, кнопки недоступны |
| Верный ключ | READY, телеметрия запрашивается |
| Разрыв связи | IDLE, попытка переподключения |
| Автопереподключение выключено | IDLE без попыток |
| Спам запущен | foreground-уведомление, счётчик растёт |
| Остановка из уведомления | спам остановлен, сервис закрыт |
| Поворот экрана | вкладка и настройки сохраняются |
| Смена темы | Activity пересоздаётся, тема применяется |
| Демо-режим | скорость и пробег меняются, команды отвечают |

## 5. Hardware-тест

Нужны:

- Android-телефон с BLE;
- самокат с известным модулем;
- доступ к включению HCI snoop log;
- желательно последовательный порт или отладочный разъём.

Порядок:

1. Включить HCI snoop log.
2. Подключиться официальным приложением или эталонным клиентом.
3. Снять лог.
4. Повторить с DanyUrent.
5. Сравнить кадры, ключи, тайминги и ответы.
6. Проверить каждую команду отдельно.
7. Зафиксировать результаты в analysis/hardware_test.md.

Без hardware-теста нельзя утверждать, что ключи и команды работают на конкретной прошивке.

## 6. Негативные проверки

- кадр с length 255 и пустым payload;
- поток из 1000 байт без заголовка;
- повторяющиеся A3 A4 с неверной длиной;
- notify приходит по одному байту;
- запись при MTU 23;
- запись при MTU 517;
- очередь из 64 чанков;
- кадр, требующий 65 чанков;
- отключение во время записи;
- отключение во время авторизации;
- повторная авторизация без переподключения;
- спам при потере связи и autoResumeSpam=true.

Часть этих сценариев не покрыта автоматически и требует instrumentation-тестов или hardware.

## 8. Критерии готовности

Для изменений в протоколе:

- unit-тест на сборку;
- тест-вектор в frames.json;
- обновление opcodes.csv;
- обновление protocol-implementation.md;
- проверка verify_frames.py.

Для изменений в UI:

- сборка debug;
- ручная проверка в демо-режиме;
- проверка всех пяти тем;
- проверка поворота.

Для изменений в BLE:

- сборка;
- проверка на телефоне;
- проверка с реальным самокатом или обоснованное указание, что проверка невозможна.
