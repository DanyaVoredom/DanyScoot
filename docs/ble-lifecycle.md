# Жизненный цикл BLE

## 1. Разрешения по версиям Android

| API | Разрешения | Особенности |
| --- | --- | --- |
| 23..30 | BLUETOOTH, BLUETOOTH_ADMIN, ACCESS_FINE_LOCATION, ACCESS_COARSE_LOCATION | для сканирования требуется включённая геолокация |
| 31..32 | BLUETOOTH_SCAN с neverForLocation, BLUETOOTH_CONNECT | геолокация для скана не требуется |
| 33..35 | BLUETOOTH_SCAN, BLUETOOTH_CONNECT, POST_NOTIFICATIONS | уведомление foreground-сервиса требует согласия |

Приложение запрашивает разрешения при старте MainActivity. Если пользователь отказал, скан и подключение не работают, но демо-режим остаётся доступен.

## 2. Проверка адаптера

Перед сканированием проверяются:

- BluetoothManager и BluetoothAdapter существуют;
- адаптер включён;
- для API ниже 31 включена геолокация;
- BluetoothLeScanner доступен;
- разрешение на скан не отозвано.

Ошибки возвращаются через Listener.onError и Listener.onScanFinished. Состояние SCANNING сбрасывается в IDLE.

## 3. Сканирование

Параметры:

- режим SCAN_MODE_LOW_LATENCY;
- длительность 15000 мс;
- фильтр по сервису 6e400001-b5a3-f393-e0a9-e50e24dcca9e при включённом фильтре UART;
- без фильтра при showAllDevices=true;
- RSSI и имя устройства показываются в списке.

При фильтре UART системный ScanFilter может не находить устройства, которые не рекламируют сервисный UUID. Поэтому предусмотрен режим показа всех устройств. Устройство с UUID UART помечается в списке.

Повторный вызов startScan во время сканирования игнорируется. stopScan снимает таймаут и вызывает stopScan у сканера.

## 4. Подключение

Порядок:

1. Остановить скан.
2. Закрыть предыдущий GATT.
3. Получить BluetoothDevice по адресу.
4. Вызвать connectGatt с TRANSPORT_LE и autoConnect=false.
5. Запустить таймаут 20000 мс.

При успешном подключении:

- connected=true;
- снимается таймаут подключения;
- вызывается onConnected;
- запрашивается MTU 247;
- запускается страховочный таймер discoverFallback на 1500 мс.

Если устройство не подключается за 20 секунд, GATT закрывается и вызывается onDisconnected с причиной timeout. Для GATT status 133 применяется задержка закрытия 150 мс, чтобы стек успел освободить ресурс.

## 5. Обнаружение сервисов

После onConnectionStateChange или onMtuChanged вызывается discoverServices. Защита от повторного вызова:

- servicesReady;
- descriptorPending;
- closing;
- проверка g === gatt.

Если сервис UART не найден, соединение закрывается с ошибкой UART service not found. Если отсутствует одна из характеристик, ошибка UART characteristics not found.

## 6. Уведомления

Используются:

- сервис 6e400001-b5a3-f393-e0a9-e50e24dcca9e;
- запись 6e400002-b5a3-f393-e0a9-e50e24dcca9e;
- уведомления 6e400003-b5a3-f393-e0a9-e50e24dcca9e;
- CCCD 00002902-0000-1000-8000-00805f9b34fb.

Порядок:

1. setCharacteristicNotification(notify, true).
2. Получить CCCD.
3. Записать ENABLE_NOTIFICATION_VALUE.
4. Дождаться onDescriptorWrite.
5. Вызвать markServicesReady.

Если CCCD отсутствует, сервис считается готовым сразу после setCharacteristicNotification. Это совместимо с устройствами, которые не требуют явной записи дескриптора.

Таймаут настройки уведомлений: 3000 мс. При ошибке соединение закрывается.

## 7. Авторизация

После onServicesReady ScooterClient отправляет кадр 0x01 с текущим ключом. Ответ обрабатывается в handleAuthFrame:

- payload[0] должен быть равен 1;
- payload[1] становится sessionKey;
- sessionKey 0 допустим;
- состояние меняется на READY;
- вызывается onAuthenticated.

Таймаут 3000 мс. При неверном ключе или таймауте состояние возвращается в READY, authenticated=false. Можно повторить ввод ключа без переподключения.

## 8. Запись

Кадр нарезается на чанки размером MTU-3, но не меньше 20 и не больше 512 байт. При MTU 23 размер чанка 20 байт. При MTU 247 размер 244 байта.

Очередь:

- максимум 64 чанка;
- проверка выполняется до добавления, с учётом всех чанков нового кадра;
- при переполнении возвращается false и пишется ошибка;
- write without response используется, если характеристика не поддерживает PROPERTY_WRITE;
- иначе используется write with response и ожидается onCharacteristicWrite;
- таймаут записи 2000 мс очищает очередь.

Запись запрещена, пока соединение не установлено и сервисы не готовы. Это защищает от отправки кадра в период discovery.

## 9. Приём

Notify-кадры могут приходить фрагментами. ScooterClient накапливает их в rxBuffer и вызывает FrameCodec.findFrames.

Правила:

- искать байт A3, затем A4;
- длина payload берётся из третьего байта;
- полный размер кадра = длина + 7;
- проверить CRC8;
- при ошибке сдвинуться на один байт и искать следующий кадр;
- хвост сохранить до следующего notify;
- при размере буфера больше 1024 байт сбросить буфер.

## 10. Потеря связи и переподключение

При разрыве:

- состояние IDLE;
- sessionKey сбрасывается;
- authPending и authenticated сбрасываются;
- rxBuffer очищается;
- спам останавливается;
- если autoResumeSpam=true, желание спама сохраняется;
- если autoReconnect=true и попытки не исчерпаны, запускается reconnect через autoReconnectDelayMs.

По умолчанию: 3 попытки, задержка 5000 мс. Диапазоны: 0..20 попыток, 500..60000 мс.

После успешной авторизации onAuthenticated повторно запрашивает телеметрию и, при необходимости, возобновляет спам.

## 11. Отключение

Явное отключение:

- отменяет переподключение;
- устанавливает linkLost=true;
- останавливает спам;
- сбрасывает счётчик попыток так, чтобы автопереподключение не сработало;
- закрывает GATT или останавливает демо;
- сбрасывает ключ и состояние в IDLE.

Закрытие GATT вызывает onDisconnected, но linkLost=true подавляет повторную обработку.

## 12. Ограничения

- Нет реального тестирования на самокате.
- Нет автоматического выбора ключа по устройству.
- Нет проверки, что устройство является самокатом Urent, кроме UUID UART и ответа на ключ.
- Нет восстановления после зависшего GATT, кроме таймаутов и повторного подключения.
- Нет фонового сканирования и работы после завершения процесса.
