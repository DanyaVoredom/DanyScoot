# Документация DanyScoot

Документация разделена на три уровня:

- docs: устройство приложения, сборка, эксплуатация и разработка.
- analysis: доказательная база по референсным APK, протоколу и ограничениям.
- references: артефакты, хеши, машиночитаемые таблицы и схемы.

## Порядок чтения

1. README.md в корне: обзор, быстрый старт, ограничения.
2. docs/architecture.md: как устроено приложение.
3. docs/ble-lifecycle.md: что происходит от сканирования до команд.
4. docs/protocol-implementation.md: как протокол отображён в коде.
5. docs/troubleshooting.md: если подключение или команда не работают.
6. analysis/protocol_full.md: полное описание протокола.
7. analysis/references.md: происхождение каждого факта.

## Статусы утверждений

В документации используются три уровня уверенности:

- confirmed: подтверждено сборщиком, декодером или манифестом в APK.
- inferred: восстановлено из декодера, тест-вектора или косвенных данных.
- catalog: известно только имя опкода, без подтверждённого payload.

Если утверждение не имеет статуса, оно описывает поведение DanyScoot, а не протокол самоката.

## Связь с кодом

Любое изменение поведения должно сопровождаться обновлением затронутого документа. Команды и опкоды дополнительно фиксируются в references/opcodes.csv, кадры в references/frames.json, а происхождение фактов в analysis/source_map.md.

## Проверка документации

Минимальная проверка после правок:

```
python references/verify_frames.py
cd app
.\gradlew.bat --no-daemon testDebugUnitTest lintDebug
```

Ссылки на файлы и якоря проверяются вручную. Внешние ссылки на APK и публичные описания могут быть недоступны и не являются обязательными для сборки.
