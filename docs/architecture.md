# Архитектура

## 1. Цели

DanyUrent решает четыре задачи:

- найти и подключить BLE-устройство с сервисом Nordic UART;
- пройти рукопожатие и получить сессионный ключ;
- отправлять команды и декодировать ответы самоката;
- сохранять настройки и показывать состояние в реальном времени.

Приложение не содержит сетевого клиента, не работает с API Urent и не выполняет серверную разблокировку. Вся логика находится в одном APK и одном процессе.

## 2. Слои

```
UI
  MainActivity, четыре фрагмента, ViewBinding
    |
Core
  ScooterClient, Prefs, LogBus
    |
BLE
  BleTransport, FrameCodec, ScooterCodec, OpcodeCatalog
    |
Android
  BluetoothLeScanner, BluetoothGatt, SharedPreferences, NotificationManager
```

Зависимости направлены вниз. BLE-слой не знает о фрагментах. UI не работает с GATT напрямую. ScooterClient является единственной точкой, которая связывает состояние транспорта, протокол и интерфейс.

## 3. Компоненты

| Компонент | Ответственность | Не делает |
| --- | --- | --- |
| MainActivity | навигация, разрешения, общий статус, badge спама | не отправляет команды |
| DevicesFragment | скан, список, выбор устройства, демо | не выполняет GATT-операции |
| ControlFragment | ключ, команды, телеметрия, консоль, спам | не парсит кадры |
| LogFragment | отображение журнала, фильтры, копирование | не хранит журнал на диске |
| SettingsFragment | ключ, интервал, переподключение, темы, демо | не подключается к самокату |
| ScooterClient | состояние, авторизация, команды, ответы, спам, демо | не сканирует BLE напрямую |
| BleTransport | скан, GATT, MTU, очередь записи, уведомления | не знает опкоды |
| FrameCodec | сборка и разбор кадра, CRC, hex | не знает семантику команд |
| ScooterCodec | payload команд и декодеры телеметрии | не управляет соединением |
| OpcodeCatalog | имена и направления опкодов | не содержит payload |
| Prefs | типизированные настройки | не содержит UI-логики |
| LogBus | кольцевой журнал и StateFlow | не пишет в файл |
| SpamService | foreground-уведомление и остановка спама | не отправляет кадры |

## 4. Состояние клиента

Состояния определены в ClientState:

| Состояние | Значение | isReady |
| --- | --- | --- |
| IDLE | нет подключения или скан остановлен | нет |
| SCANNING | идёт поиск устройств | нет |
| CONNECTING | создаётся GATT-соединение | нет |
| DISCOVERING | обнаружение сервисов и настройка уведомлений | нет |
| AUTHENTICATING | отправлен ключ, ожидается ответ | нет |
| READY | соединение установлено, ключ принят | да, если authenticated |
| DEMO | виртуальный самокат | да |
| ERROR | зарезервировано для ошибок | нет |

Переходы:

```
IDLE -> SCANNING -> IDLE
IDLE -> CONNECTING -> DISCOVERING -> AUTHENTICATING -> READY
READY -> IDLE при потере связи или отключении
IDLE -> DEMO при выборе демо-самоката
DEMO -> IDLE при отключении
```

AUTHENTICATING при неверном ключе или таймауте возвращается в READY. Это позволяет повторить ввод ключа без переподключения. Кнопки команд при этом остаются недоступны, потому что isReady требует authenticated.

## 5. Потоки данных

### Сканирование

```
BluetoothLeScanner
  -> ScanCallback
  -> BleTransport.Listener.onDevice
  -> ScooterClient._devices
  -> DevicesFragment adapter
```

BleTransport не фильтрует устройства по имени. Фильтр UART применяется либо на уровне ScanFilter, либо в ScooterClient при добавлении в список. Режим показа всех устройств задаётся настройкой showAllDevices.

### Подключение и авторизация

```
ScooterClient.connect
  -> BleTransport.connect
  -> onConnectionStateChange
  -> discoverServices
  -> onServicesDiscovered
  -> включение notify и CCCD
  -> onServicesReady
  -> ScooterClient.authenticate
  -> кадр 0x01
  -> ответ 0x01
  -> sessionKey
```

### Приём кадров

```
GATT notification
  -> BleTransport.onFrame
  -> ScooterClient.processFrame
  -> FrameCodec.findFrames
  -> handleFrame
  -> LogBus и StateFlow
```

Буфер приёма хранится в ScooterClient. При переполнении свыше 1024 байт он сбрасывается с предупреждением. Кадры, не прошедшие CRC, отбрасываются, а поиск продолжается со следующего байта A3.

### Отправка кадров

```
UI
  -> ScooterClient
  -> FrameCodec.build
  -> BleTransport.write
  -> нарезка на чанки
  -> очередь
  -> GATT write
```

Очередь последовательная. Следующий чанк отправляется только после onCharacteristicWrite или сразу после write для write without response. Таймаут записи 2000 мс очищает очередь.

## 6. Потоки выполнения

Все публичные методы BleTransport и ScooterClient вызываются с main thread. Callback-и GATT приходят на binder-потоке и перекладываются в Handler(Looper.getMainLooper()). Это упрощает состояние, но требует, чтобы обработчики не блокировали main thread.

Сканирование и GATT-операции выполняются системой. Приложение не создаёт собственных потоков. Kotlin coroutines используются только во фрагментах для сбора StateFlow через repeatOnLifecycle.

## 7. Жизненный цикл

Application создаёт ScooterClient и BleTransport один раз. Клиент является singleton-объектом и переживает пересоздание Activity. Фрагменты скрываются и показываются через FragmentTransaction, поэтому onHiddenChanged обновляет поля из Prefs.

При завершении Activity вызывается stopScan. GATT-соединение не закрывается автоматически при повороте экрана. Явное отключение выполняется кнопкой или через настройки при смене демо-режима.

SpamService является foreground-сервисом с типом connectedDevice. Он запускается только после успешной авторизации и останавливается кнопкой, уведомлением или потерей соединения, если автовозобновление отключено.

## 8. Обработка ошибок

Ошибки делятся на четыре группы:

- разрешения и адаптер: Bluetooth выключен, нет разрешения, BLE не поддерживается;
- соединение: таймаут 20 секунд, GATT 133, разрыв, отсутствие сервиса;
- авторизация: таймаут 3 секунды, неверный ключ, пустой ответ;
- протокол: плохой CRC, неизвестный опкод, короткий payload, переполнение буфера.

Ошибки не приводят к аварийному завершению. Они записываются в LogBus, меняют состояние и, где предусмотрено, запускают переподключение. Подробная диагностика: docs/troubleshooting.md.

## 9. Демо-режим

Демо-режим полностью обходит BleTransport. Команды проходят через writeCommand, журналируются и получают синтетический ответ через demoReply. Скорость меняется каждые 1500 мс, пробег растёт, запас хода уменьшается. Это позволяет проверить UI, журнал, темы и сценарии без BLE.

Демо-режим не доказывает работоспособность протокола. Он проверяет только внутреннюю согласованность приложения.

## 10. Границы ответственности

Приложение не хранит историю поездок, не содержит карт, аккаунтов, платежей и сетевой телеметрии. Все данные, кроме настроек и журнала в памяти, остаются на устройстве. Журнал исчезает при завершении процесса.

Протокол и ключи взяты из сторонних APK. Приложение не гарантирует совместимость с конкретной прошивкой и не заменяет официальный клиент Urent.
