# Архитектура

## 1. Цели

DanyScoot решает пять задач:

- найти и подключить BLE-устройство с сервисом Nordic UART, Edifier или универсальным GATT-профилем;
- пройти рукопожатие и получить сессионный ключ для самоката;
- отправлять команды и декодировать ответы самоката;
- читать данные и выполнять GATT-операции для гарнитур и прочих устройств;
- сохранять настройки, показывать состояние и выполнять действия через AI-инструменты.

Приложение не содержит клиента API Urent и не выполняет серверную разблокировку. Сеть используется для запросов к настроенному AI-серверу и проверки релизов Codeberg. Вся логика работы с BLE находится в одном APK и одном процессе.

## 2. Слои

```
UI
  MainActivity, пять фрагментов, AiActivity, ViewBinding
    |
AI
  AiClient, AiTools, AiChat
    |
Core
  ScooterClient, Prefs, LogBus, UpdateManager
    |
BLE
  BleTransport, BleProfiles, DeviceKind, GattInfo, FrameCodec, ScooterCodec, OpcodeCatalog
    |
Android
  BluetoothLeScanner, BluetoothGatt, SharedPreferences, NotificationManager, PackageInstaller
```

Зависимости направлены вниз. BLE-слой не знает о фрагментах. UI не работает с GATT напрямую. ScooterClient является единственной точкой, которая связывает состояние транспорта, протокол и интерфейс. AI-слой вызывает ScooterClient и Prefs через инструменты на main thread.

## 4. Состояние клиента

Состояния определены в ClientState:

| Состояние | Значение | isReady |
| --- | --- | --- |
| IDLE | нет подключения или скан остановлен | нет |
| SCANNING | идёт поиск устройств | нет |
| CONNECTING | создаётся GATT-соединение | нет |
| DISCOVERING | обнаружение сервисов и настройка уведомлений | нет |
| AUTHENTICATING | отправлен ключ, ожидается ответ | нет |
| READY | соединение установлено, ключ принят | да, если authenticated или устройство внешнее |
| ERROR | зарезервировано для ошибок | нет |

Переходы:

```
IDLE -> SCANNING -> IDLE
IDLE -> CONNECTING -> DISCOVERING -> AUTHENTICATING -> READY
READY -> IDLE при потере связи или отключении
```

AUTHENTICATING при неверном ключе или таймауте возвращается в READY. Это позволяет повторить ввод ключа без переподключения. Кнопки команд при этом остаются недоступны, потому что isReady требует authenticated.

## 5. Потоки данных

### Сканирование

```
BluetoothLeScanner
  -> ScanCallback
  -> BleTransport.Listener.onDevice
  -> ScooterClient._devices
  -> DevicesFragment adapter
```

BleTransport не фильтрует устройства по имени. Фильтр UART применяется либо на уровне ScanFilter, либо в ScooterClient при добавлении в список. Режим показа всех устройств задаётся настройкой showAllDevices.

### Подключение и авторизация

```
ScooterClient.connect
  -> BleTransport.connect
  -> onConnectionStateChange
  -> discoverServices
  -> onServicesDiscovered
  -> включение notify и CCCD
  -> onServicesReady
  -> ScooterClient.authenticate
  -> кадр 0x01
  -> ответ 0x01
  -> sessionKey
```

### Приём кадров

```
GATT notification
  -> BleTransport.onFrame
  -> ScooterClient.processFrame
  -> FrameCodec.findFrames
  -> handleFrame
  -> LogBus и StateFlow
```

Буфер приёма хранится в ScooterClient. При переполнении свыше 1024 байт он сбрасывается с предупреждением. Кадры, не прошедшие CRC, отбрасываются, а поиск продолжается со следующего байта A3.

### Отправка кадров

```
UI
  -> ScooterClient
  -> FrameCodec.build
  -> BleTransport.write
  -> нарезка на чанки
  -> очередь
  -> GATT write
```

Очередь последовательная. Следующий чанк отправляется только после onCharacteristicWrite или сразу после write для write without response. Таймаут записи 2000 мс очищает очередь.

## 6. Потоки выполнения

Все публичные методы BleTransport и ScooterClient вызываются с main thread. Callback-и GATT приходят на binder-потоке и перекладываются в Handler(Looper.getMainLooper()). Это упрощает состояние, но требует, чтобы обработчики не блокировали main thread.

Сканирование и GATT-операции выполняются системой. Приложение не создаёт собственных потоков. Kotlin coroutines используются только во фрагментах для сбора StateFlow через repeatOnLifecycle.

## 7. Жизненный цикл

Application создаёт ScooterClient и BleTransport один раз. Клиент является singleton-объектом и переживает пересоздание Activity. Фрагменты скрываются и показываются через FragmentTransaction, поэтому onHiddenChanged обновляет поля из Prefs.

При старте Application проверяет наличие обновлений не чаще раза в сутки, если включена настройка autoUpdate. Скачанный APK хранится в cacheDir/updates и устанавливается по кнопке в настройках.

При завершении Activity вызывается stopScan. GATT-соединение не закрывается автоматически при повороте экрана. Явное отключение выполняется кнопкой или при подключении к другому устройству.

SpamService является foreground-сервисом с типом connectedDevice. Он запускается только после успешной авторизации и останавливается кнопкой, уведомлением или потерей соединения, если автовозобновление отключено.

## 8. Обработка ошибок

Ошибки делятся на четыре группы:

- разрешения и адаптер: Bluetooth выключен, нет разрешения, BLE не поддерживается;
- соединение: таймаут 20 секунд, GATT 133, разрыв, отсутствие сервиса или характеристик;
- авторизация: таймаут 3 секунды, неверный ключ, пустой ответ;
- протокол: плохой CRC, неизвестный опкод, короткий payload, переполнение буфера.

При обнаружении сервисов BleTransport публикует полный дамп в LogBus и во вкладку GATT. Если Nordic UART отсутствует, выполняется одна повторная попытка discovery, после чего устройство помечается несовместимым до успешной авторизации, а автопереподключение блокируется. Это отличает закрытую прошивку от временного сбоя GATT.

Ошибки не приводят к аварийному завершению. Они записываются в LogBus, меняют состояние и, где предусмотрено, запускают переподключение. Подробная диагностика: docs/troubleshooting.md.

## 9. Профили и внешние устройства

Профиль выбирается при подключении по типу устройства. Для самоката используется Nordic UART: запись в RX, уведомления из TX. Для гарнитуры Edifier используются сервис 00001100-d102-11e1-9b23-00025b00a5a5 и характеристики 1101, 1102, 1103; батарея читается из 180F/2A19, расширенные данные из 48091601, метаданные из стандартных сервисов Device Information.

Если известный профиль не найден, BleTransport перебирает writable и notifiable характеристики в одном сервисе, пропуская служебные сервисы и Fast Pair. Внешнее устройство не проходит рукопожатие самоката: isReady считается истинным при наличии связи и профиля. Команды самоката для него блокируются, а чтение, запись и подписка доступны через GATT-инструменты AI.

Чтение характеристики из AI возвращает ответ через отложенный результат: запросы по одному UUID заменяют друг друга, а таймаут возвращает ошибку без ответа. Ответ приходит в onCharacteristicRead и завершает ожидание копией данных.

Каждый кадр уведомления передаётся в ScooterClient вместе с UUID характеристики. Для самоката кадры проходят FrameCodec, для внешнего устройства сохраняются в кольцевой буфер уведомлений и в журнал.

## 10. Границы ответственности

Приложение не хранит историю поездок, не содержит карт, аккаунтов и платежей. Все данные, кроме настроек, журнала в памяти и скачанного APK обновления, остаются на устройстве. Журнал исчезает при завершении процесса. Сетевой обмен ограничен запросом релиза, загрузкой APK и обращениями к настроенному AI-серверу.

Протокол и ключи взяты из сторонних APK. Приложение не гарантирует совместимость с конкретной прошивкой и не заменяет официальный клиент Urent.
