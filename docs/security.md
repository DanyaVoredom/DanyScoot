# Безопасность

## 1. Модель угроз

Рассматриваемые угрозы:

- перехват BLE-трафика рядом с самокатом;
- подбор ключа;
- повторное воспроизведение кадра;
- доступ к настройкам и журналу через backup или root;
- утечка ключа через скриншот, logcat или отчёт об ошибке;
- вредоносное BLE-устройство, которое отвечает неожиданными кадрами;
- утечка данных в AI-сервер или перехват запроса к нему;
- компрометация API-ключа AI.

Не рассматриваются:

- компрометация самой прошивки;
- атаки на серверы Urent;
- атаки через официальное приложение;
- физический доступ к отладочному порту самоката.

## 2. Что защищено

- Кадр имеет CRC8, поэтому случайные ошибки обнаруживаются.
- Сессионный ключ меняется после переподключения.
- Команды не отправляются до успешной авторизации.
- BLE-ключ не передаётся в сеть.
- android:allowBackup=false.
- Нет экспортируемых сервисов и провайдеров.
- SpamService и AiActivity не экспортированы.
- AI-запросы уходят только по инициативе пользователя.

## 3. Что не защищено

- BLE-канал не шифруется приложением. XOR с rand не является криптографией.
- Ключ хранится в SharedPreferences в открытом виде.
- sessionKey передаётся в кадре и может быть перехвачен.
- Нет защиты от replay-атак. Спам использует время, но обычные команды не имеют nonce.
- Нет аутентификации самоката. Приложение доверяет любому устройству с UUID UART.
- Нет проверки сертификата или подписи прошивки.
- Нет ограничения на количество попыток ключа.
- Нет блокировки опасных команд.
- Журнал содержит чувствительные данные и не очищается автоматически.
- BLE-ключ не маскируется в поле настроек.
- API-ключ AI хранится в открытом виде и уходит в заголовке запроса.
- Разрешён cleartext HTTP, поэтому локальный AI-сервер может быть перехвачен.
- История AI-чата и результаты инструментов уходят на сервер провайдера.

## 4. Разрешения

| Разрешение | Зачем | Риск |
| --- | --- | --- |
| BLUETOOTH_SCAN | поиск устройств | раскрывает окружающие BLE-устройства |
| BLUETOOTH_CONNECT | подключение и команды | доступ к спаренным устройствам |
| ACCESS_FINE_LOCATION до API 30 | требование Android для скана | чувствительно, но не используется для карт |
| POST_NOTIFICATIONS | уведомление спама | минимальный |
| FOREGROUND_SERVICE_CONNECTED_DEVICE | работа спама | удержание процесса |
| INTERNET | AI-сервер и проверка релизов | передача текста чата и состояния устройства |
| REQUEST_INSTALL_PACKAGES | установка скачанного APK | пользователь подтверждает установку |

Приложение не запрашивает камеру, контакты, хранилище, VPN, QUERY_ALL_PACKAGES и MANAGE_EXTERNAL_STORAGE. Это отличие от FishBot и официального Urent.

## 5. Хранение ключа

Текущее хранение:

- файл danyscoot_prefs.xml в приватном каталоге;
- BLE-ключ в открытом виде;
- API-ключ AI в открытом виде;
- последний MAC-адрес;
- имя и тип устройства.

Риски:

- root;
- backup через отладочный мост;
- физический доступ к разблокированному устройству;
- ошибка в другом приложении с тем же uid.

Рекомендации:

- для публичной сборки использовать Android Keystore и шифрование ключей;
- не печатать ключи в журнал;
- маскировать ключи в UI;
- добавить очистку ключа при удалении приложения;
- не включать отладочный экспорт.

## 6. Журнал

Журнал может содержать:

- полные кадры;
- IMEI;
- RFID;
- MAC-адреса;
- имена окружающих устройств;
- session key и hex-кадры.

Статический BLE-ключ в журнал не пишется. Меры:

- не публиковать журнал без очистки;
- не делать скриншоты с ключом;
- добавить маскирование поля ключа в UI;
- добавить экспорт с предупреждением;
- ограничить срок жизни журнала.

## 7. Сетевые риски

DanyScoot использует сеть для проверки обновлений и загрузки APK с GitHub, а также для запросов к настроенному AI-серверу. Запрос релиза не содержит пользовательских данных. AI-запрос содержит историю чата и результаты инструментов, включая состояние устройства и журнал, если модель их запросила. BLE-ключ в AI-запрос не включается.

Для установки APK добавлено разрешение REQUEST_INSTALL_PACKAGES и FileProvider. Для локальных AI-серверов разрешён cleartext HTTP через android:usesCleartextTraffic=true. Это осознанный компромисс: трафик к локальному серверу можно перехватить, а API-ключ передаётся в открытом виде.

Правила для сетевого кода:

- TLS с проверкой сертификата для внешних серверов;
- cleartext только для localhost или доверенной локальной сети;
- минимальный набор разрешений;
- загрузка APK только с доверенного хоста;
- проверка версии и имени APK-ассета;
- установка только по действию пользователя;
- API-ключ не писать в журнал и не включать в отчёты.

## 8. BLE-риски

- Поддельное устройство может имитировать UUID UART.
- Ответ 0x01 может быть подделан.
- Команды могут быть перехвачены и повторены.
- Спам создаёт нагрузку на канал и может мешать другим операциям.
- Нет ограничения на количество подключений и попыток.

Меры:

- проверять имя и адрес устройства;
- не подключаться к незнакомым устройствам;
- использовать спам только на своём самокате;
- останавливать спам при потере контроля;
- проверять журнал на неожиданные команды.

## 9. Безопасность сборки

- Release использует debug-подпись. Это не публичный артефакт.
- minify отключён, код читаем.
- Нет certificate pinning: AI-сервер задаётся пользователем, а релизы идут с публичного API.
- Нет проверки целостности APK.
- Нет обфускации.

Для публичной сборки нужно:

- постоянный keystore;
- minify и R8;
- удаление отладочных логов;
- маскирование ключей;
- проверка exported-компонентов;
- подпись release.

## 10. Ответственное раскрытие

Если найдена уязвимость:

1. Не публиковать рабочий эксплойт.
2. Описать шаги и влияние.
3. Приложить версию, телефон, самокат.
4. Дать время на исправление.
5. Не прикладывать чужие ключи и персональные данные.

## 11. Остаточные риски

- Ключи из референсов могут быть уже отозваны.
- Прошивка может принимать команды от любого клиента с ключом.
- Пользователь может отправить в AI-сервер чувствительные данные.
- Ответственность за правомерность использования лежит на пользователе.
