# Методика анализа

## 1. Принципы

- Не угадывать протокол.
- Отделять подтверждённые факты от предположений.
- Указывать источник для каждого важного утверждения.
- Проверять кадры независимым скриптом.
- Не запускать подозрительные APK на основном устройстве.
- Не публиковать чужие ключи и персональные данные.

## 2. Инструменты

| Инструмент | Версия | Назначение |
| --- | --- | --- |
| apktool | 3.0.3 | ресурсы, манифест, smali |
| jadx | 1.5.6 | Java-декомпиляция LostBot и FishBot |
| aapt | из Android SDK | badging, манифест |
| apksigner | из Android SDK | подпись |
| Python | 3.x | проверка кадров и CSV |
| Wireshark | любая | HCI snoop |
| nRF Connect | Android | GATT-диагностика |

## 3. Порядок

1. Зафиксировать хеш и размер APK.
2. Проверить подпись.
3. Разобрать манифест.
4. Найти BLE-классы и UUID.
5. Восстановить кадр и CRC.
6. Найти рукопожатие и ключи.
7. Собрать команды и ответы.
8. Сравнить клиенты.
9. Записать тест-векторы.
10. Проверить векторы независимым скриптом.
11. Отметить неизвестные.
12. Обновить документацию.

## 4. Уровни уверенности

confirmed:

- есть сборщик кадра;
- есть декодер ответа;
- есть манифест или ресурс;
- есть независимый тест-вектор.

inferred:

- payload восстановлен из декодера;
- имя и код известны, но сборщик не найден;
- единицы выведены из кода, но не проверены на устройстве.

catalog:

- известно только имя из каталога;
- payload и ответ неизвестны.

## 5. Проверка кадров

references/frames.json содержит фиксированный rand, поэтому кадры детерминированы. verify_frames.py:

- читает JSON;
- собирает кадр;
- сравнивает hex;
- разбирает обратно;
- проверяет CRC8;
- проверяет CRC16 для прошивки;
- сообщает ok или ошибку.

Запуск:

```
python references/verify_frames.py
```

Ожидаемый вывод: ok 72.

## 6. Проверка CSV

```
python -c "import csv; r=list(csv.DictReader(open('references/opcodes.csv',encoding='utf-8'))); print(len(r))"
```

Ожидаемый вывод: 54.

## 7. Динамический анализ

Для сети:

- изолированное устройство или эмулятор;
- прокси;
- отключение доступа к личным аккаунтам;
- проверка разрешений.

Для BLE:

- HCI snoop;
- nRF Connect;
- эталонный клиент;
- сравнение кадров;
- повтор на тестовом самокате.

## 8. Ограничения методики

- Статический анализ не показывает фактическое поведение.
- Обфускация может скрывать код.
- Отсутствие строки не доказывает отсутствие функции.
- Наличие разрешения не доказывает использование.
- Без hardware нельзя подтвердить протокол.
- Официальные APK не являются истиной для всех версий.

## 9. Этика

- Анализировать только свои устройства и свои APK.
- Не помогать с доступом к чужому транспорту.
- Не публиковать эксплойты.
- Не прикладывать чужие ключи.
- Уважать лицензии и товарные знаки.
