# Тест-векторы

## 1. Состав

references/frames.json:

- crc8 и crc16 параметры;
- 48 TX кадров;
- 20 RX кадров;
- 4 битых кадра.

Всего 72 проверки. Кадры детерминированы: rand, key и payload заданы явно. Это позволяет сравнивать реализацию независимо от Random.

## 2. Схема

Каждый TX-элемент содержит:

- id;
- cmd;
- key;
- rand;
- wire_rand;
- payload в hex;
- frame в hex;
- note.

RX-элементы содержат:

- id;
- cmd;
- payload в hex;
- note.

Битые кадры содержат:

- id;
- frame;
- error;
- note.

## 3. Примеры

Рукопожатие NineHack:

```
A3 A4 08 33 01 00 35 43 4A 4F 76 68 36 36 E7
```

Поля:

- length 08;
- wireRand 33;
- rand 01;
- key в кадре 01, после XOR равен 00;
- cmd в кадре 00, после XOR равен 01;
- payload в кадре 35 43 4A 4F 76 68 36 36, после XOR равен 34 42 4B 4E 77 69 37 37, то есть 4BKNwi77.

Рукопожатие LostBot:

```
A3 A4 08 33 01 00 76 35 52 32 49 70 6F 34 89
```

Разблокировка NineHack:

```
A3 A4 0A 33 01 04 00 00 00 00 00 00 00 00 00 00 31
```

Спам с временем 1700000000:

```
A3 A4 0A 42 52 15 11 21 21 22 29 75 43 E1 10 10 F9
```

Ошибка 0x10:

```
payload 15 02
```

означает отклонённую команду 0x15 с причиной 2.

Битые кадры:

- bad_crc: CRC mismatch;
- bad_len: length mismatch;
- bad_header: A2 A4;
- too_short: 6 байт.

## 4. Генерация

```
python references/generate_frames.py
```

Скрипт создаёт frames.json без внешних зависимостей. После изменения генератора нужно проверить diff и не коммитить случайные изменения rand.

## 5. Проверка

```
python references/verify_frames.py
```

Ожидаемый вывод: ok 72.

Скрипт независимо:

- собирает кадр из полей;
- сравнивает hex;
- разбирает кадр;
- проверяет CRC8;
- проверяет CRC16;
- проверяет битые кадры на ожидаемую ошибку.

## 6. Правила изменения

- Не редактировать frames.json вручную, если можно изменить генератор.
- Не менять существующие id без причины.
- Новый кадр должен иметь уникальный id.
- Для нового кадра указывать источник и статус уверенности.
- Для RX указывать, что означает payload.
- Для битого кадра указывать ожидаемую ошибку.

## 7. Ограничения

- Векторы проверяют кодирование, а не поведение прошивки.
- CRC может совпасть на повреждённых данных, но это маловероятно.
- Нет векторов для всех 54 опкодов.
- Нет векторов для чанков BLE.
- Нет векторов для очереди записи.
- Нет векторов для 0xFB и 0xFC с реальным образом.

## 8. Связь с кодом

Unit-тесты используют те же формулы, но не читают frames.json. Это сделано намеренно: тест не зависит от внешнего файла и работает в JVM.

Для полной проверки используется отдельный Python-скрипт. Он не входит в Gradle-сборку.
