# Прошивка и OTA

## 1. Статус

DanyUrent не обновляет прошивку. Команды 0xFA, 0xFB и 0xFC используются только для чтения информации и логирования. Полный OTA-сценарий восстановлен по LostBot, но не проверен на hardware.

## 2. Команды

| Код | Название | Направление | Назначение |
| --- | --- | --- | --- |
| 0xFA | FW_DEVICE_INFO | TX/RX | чтение конфига и версии |
| 0xFB | FW_DEVICE_DATA | TX/RX | старт передачи и статус |
| 0xFC | FW_GET_FIRMWARE_DATA | TX/RX | запрос пакета и данные |

## 3. Чтение конфига 0xFA

Запрос: пустой payload.

Ответ: 0xFB.

Формат ответа:

| Смещение | Поле | Примечание |
| --- | --- | --- |
| 0 | статус | 1 или 2 |
| 1..2 | totalPack | u16 BE |
| 5 | deviceType | тип устройства |

После ответа LostBot запрашивает пакеты через 0xFC. Таймаут чтения конфига: 5000 мс.

## 4. Старт передачи 0xFB

TX payload:

| Поле | Размер | Примечание |
| --- | --- | --- |
| kind | 1 | тип передачи |
| totalPack | 2 | u16 BE |
| crc16 | 2 | CRC16 образа |
| type | 1 | тип устройства |
| key | 1 | ключ передачи |

CRC16 считается по всему образу: полином 0xA001, init 0xFFFF, контрольное значение 4B37.

Ответ:

| Код | Значение |
| --- | --- |
| 0 | ошибка ключа или пароля |
| 1 | устройство готово |
| 2 | передача завершена |
| 3 | таймаут приёма |
| 4 | ошибка CRC образа |

## 5. Пакеты 0xFC

TX:

- idx u16 BE;
- type u8.

RX:

- idx u16 BE; или
- idx u16 BE, data 16 байт, crc16 u16.

LostBot собирает пакеты по 16 байт, проверяет CRC и отправляет следующий запрос. Размер пакета и количество определяются totalPack.

## 6. Ключ передачи

В LostBot есть prefs transmission_device_type и transmission_update_key. Ключ передачи не равен BLE-ключу. Значение по умолчанию и алгоритм не подтверждены для всех прошивок.

## 7. Риски

- Неверный образ может вывести самокат из строя.
- Прерывание питания во время записи опасно.
- CRC16 защищает от случайных ошибок, но не от подмены.
- Нет проверки подписи прошивки.
- Нет отката.
- Нет официального источника образа.
- Ключ передачи может быть уникальным.

## 8. Почему OTA не реализован

- Нет проверенного образа.
- Нет hardware-теста.
- Нет подтверждения формата 0xFB для конкретной модели.
- Нет безопасного восстановления.
- Ошибка может привести к кирпичу.

Для реализации нужны:

- дамп текущей прошивки;
- официальный OTA-лог;
- проверка на тестовом самокате;
- восстановление через UART или загрузчик;
- подпись и контроль версии.

## 9. Что делает DanyUrent

- Отправляет 0xFA с пустым payload по кнопке чтения конфига.
- Логирует ответ 0xFB.
- Логирует запросы 0xFC.
- Показывает статус передачи.
- Не отправляет 0xFB на запись.
- Не передаёт образ.
